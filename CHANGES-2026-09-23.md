## 🚀 Headline Features

### 🎒 Gear, Shopping, Meals & Personal Lists
- Bottom tab navigation with four working screens
- **Live sync**: SWR polling (15s) plus revalidate-on-focus, so five people editing the same lists see each other's changes
- **Race-safe gear claims**: a transaction with a row lock means two people can't both grab the last gas stove. Tested against Neon: two simultaneous claims on the last 3 units gave exactly one success.
- Open-quantity items ("הרבה" / "כמה שיותר") are uncapped, and optional gear is excluded from the coverage count
- Permissions are enforced server-side: only shoppers can mark items bought, and personal items are always scoped to the session user
- UI for creating new gear items (the API existed, but nothing on the page used it)

### 🧭 Dashboard (Phase 3)
- ⏳ **Live countdown**, rendered client-side in Israel time so server and browser never disagree
- ☀️ **3-day weather forecast** from Open-Meteo, cached for an hour
- 📍 Waze and Google Maps hand-off
- 🍳 **Next-meal card**: slots are anchored to 08:00 / 13:00 / 19:00 and compared in `Asia/Jerusalem`
- 🔵 Progress rings for gear coverage
- 👋 **4-card swipe onboarding**, shown on first login and replayable from the profile
- 🐛 Fixed a bidi bug where the date range rendered *end-first* in the RTL paragraph, so the trip looked like it ran backwards

### 🏆 Contribution Leaderboard
- A podium on the dashboard links to a full board with score breakdowns and titles
- ⚖️ **Fairness**: only shoppers can buy, so the headline score counts only actions everyone can take (claiming, packing, adding). Shopping gets its own title.
- 🛡️ **Anti-gaming**: extra units are capped at +2 per item, so a "99 logs" claim can't win for free
- 🔒 `personal_items` is never touched by scoring. Verified byte-identical output after inserting private items.
- 🛒 **Anyone can add to the shopping list**. Noticing a gap isn't a privileged act, and only buying stays restricted. Duplicate names return a clean Hebrew `409` instead of a `500`.

### 📧 Email Reminders
- Gmail SMTP via nodemailer, with **4 types**:
  - 🧰 Unclaimed gear goes to everyone
  - ⏳ Countdown goes to everyone
  - 🎒 Packing is personalised per person
  - 🛒 Shopping goes to the two shoppers only
- Sent from an **admin-only panel with a preview** of the exact text, since there's no undo
- 🔐 The endpoint reads only `type` from the body. Recipients come from the users table, so it can't be used as an open relay. No email includes anything from `personal_items`.

### 📲 WhatsApp-Ready Sharing
- `format-lists.ts` renders Hebrew text shared by the copy buttons **and** the emails, so the two can't drift apart
- `CopyButton` takes a **synchronous** `getText`, because iOS Safari drops the user gesture if you `await` first
